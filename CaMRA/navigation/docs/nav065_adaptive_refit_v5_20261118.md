# NAV-065 v5：训练边界覆盖诊断与有限补采方案

本轮按用户指定的create-plan-worklog-legacy推进，由主agent做基础验证，没有专用测试子agent。任务仍是NAV-065，计划1.3.1，NAV-064依赖已满足；本轮只做诊断、隔离入口、验证及资源提案，没有新的正式采样、critic更新或development重评。NAV-065仍false，52/67，新G4仍FAIL，NAV-066不执行。

## 为什么补采

上一轮v4在540条train起点上已满足原门槛；复用180条development时，主预算36/36正确，但四个紧预算起点错误放行。固定策略能到达和评价网络能准确判断最低预算是两个要求。当前推进的是后者，不是要求策略找全局最省路径，也不是重训actor。

[只读覆盖报告](../reports/nav065_train_coverage_v5_attempt3.json)重新核验六份v4模型、原540条train/207298步及上游绑定资源，未重算development预测。六个候选各18张train图都存在相邻预算的可行性转换，原始夹区宽度均为k=0.15。已有五档没有观测到可行性反转，但这不是连续区间单调性的证明。

| 候选 | 90个起点中abs(W真值)≤0.01的数量 | 有转换的训练地图 |
| --- | ---: | ---: |
| 无校准seed0 | 4 | 18/18 |
| 无校准seed1 | 5 | 18/18 |
| 无校准seed2 | 5 | 18/18 |
| 完整方法seed0 | 12 | 18/18 |
| 完整方法seed1 | 12 | 18/18 |
| 完整方法seed2 | 11 | 18/18 |

总计49/540个起点接近零边界。0.01仅是本报告的覆盖统计刻度，沿用固定550 J尺度；不是新验收阈值。不同停止分量可以主导W，不能将所有W数值直接当作超支J。现有证据支持“边界样本较稀疏、值得有限补采”，不能证明这是全部泛化误判的唯一原因，或保证补采必过G4。

## 与参考方法的关系

参考论文的固定部署策略评价与预算搜索逻辑，以及RC-PPO的`EC-EFPPO.py`和`root_finding.py`，都要求使用匹配策略的两个评价网络组成预算判据。我们保持预算增广、不可逆安全历史、同一共同停止点和`W=max(V_h,V_c-z/550)`，beta=0。新采样/优化策略属于工程改进，不宣称论文对它提供了额外保证。

预算进入actor观测，换预算可能换路线、动作和共同停止点。因此不能拿旧轨迹只减一个新预算就当作新标签。新版每个k都调用现有`eval_r14_repair.rollout`完整运行固定actor，再调用原`deployment_oracle.reconstruct_truth`重建未折扣J和共同停止真值。使用原18张train图，development失败例不会进入拟合。

## 已实现入口

[脚本](../scripts/refit_nav065_adaptive.py)有两个互斥模式：

- `--diagnose <新报告路径>`：只读旧train、模型和输入绑定，采样/优化/development评分均为0。
- `--registration <独立批准登记>`：先验证批准、SHA256、逐项资源及代码绑定，再建立新run。原[提案](../config/nav065_adaptive_refit_proposal_v5.json)为`approved=false`，不能用来执行。

采样对每个actor×train地图额外取4档：优先平分已观测可行性转换中最宽的相邻区间；无转换才平分最宽空档，同宽取较低k。每次保留全轨迹并重新判真值，记录非单调反转。若唯一交界连续被细分，0.15可收窄到0.009375；不把该条件推演当作已取得的采样结果。

拟合只更新双critic，使用原共同停止目标；原起点/沿途/边界回归外，在每条轨迹起点和最多8个接近边界的内部状态上增加分量及联合W的符号拟合。精确原目标的辅助损失为0，目标值与部署判据不变。继承v4梯度投影，逐试步保护旧train数值/主档及已有正确起点；新样本数值单列检查，不能用大量容易样本稀释旧误差。选定内部边界状态也要满足拟定train符号检查；它是额外经验训练守卫，不改变原G4。

所有被拒试步均计额度并恢复模型、优化器；首个train通过点即冻结。已满足全部新train条件的模型零更新。六组train全通过并保存/CPU重载后，才调用原`refit_nav065_deployment.evaluate`统一复验180条旧development一次；仍由原G4决定能否生成部署包。失败就停止，不重试或挪用额度。
