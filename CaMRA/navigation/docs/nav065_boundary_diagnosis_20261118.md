# NAV-065 预算边界诊断与下一步

当前是“策略会走，预算判断器还不够可靠”。NAV-064 的主预算导航验收仍有效；NAV-065 的六个部署候选均未过零假可行标准，G4 保持 FAIL，NAV-066 未开始。

本次由主 agent 在 tiger11/tmux 直接验证，未再安排测试子 agent。复用540条 train、180条 development 轨迹及拟合前后冻结网络，新增回合、优化更新和阈值修改均为0。计算入口为[只读诊断脚本](../scripts/analyze_nav065_boundary.py)，逐回合及散列证据为[诊断报告](../reports/nav065_boundary_diagnosis_v1.json)。诊断不进行部署包发布，也不选择新的策略或 checkpoint。

| --- | ---: | ---: |
| train 假可行 / 540 | 3 | 13 |
| development 假可行 / 180 | 3 | 9 |

平均拟合变好了，零界判断却变差了。旧模型平均高估成本，带有保守偏差；重拟合去掉了这种偏差，也增加了错误放行。这是已有轨迹上观察到的变化，不能据此认定某个优化器参数是唯一原因。训练图自身也有13次假可行，因此不能把问题全部归为开发地图泛化，也不能直接断言多采轨迹就能解决。

九次开发误判的成本预测均低于共同停止真值，低估2.35–10.97 J，足以将成本减预算的正数变成负数。八次共同停止在真正到达之前：reach 真值是约0.0012–0.0068的小正数，网络却预测为负；另一次共同停止就在终点，reach 真值本来就是−3，必须由成本通道挡住超支。两路判断在这九例均未挡住，所以 `max(V_h,V_c-z/550)` 错误落到零以下。

共同停止的两个目标不是“最终总花费”和“是否到达”两个独立标签。预算偏紧时，共同停止可以选在终点前；稍宽时可以选终点，reach 目标会从接近零的正数变为−3。连续网络对这种变化的近似以及少量成本低估，均可能影响零界。原90次拟合仅优化两个回归误差，未设置训练集预算符号的放行检查；MSE下降不能替代该检查。目标与零界之间的这种敏感性有数据支持，但本次没有通过对照训练证明某种改法必然奏效。

CPU重算与原开发预测逐行一致（最大差0），原始J账本及预算编码检查通过。现有证据不支持将这九次误判解释为浮点舍入、预算单位混用或actor退化。RC-PPO 的[共同停止调用](../../../RC-PPO/rl/EC-EFPPO.py)和[预算搜索](../../../RC-PPO/rl/root_finding.py)都依赖双critic联合值；论文的价值判据不保证有限样本神经网络在每个零界附近都预测正确。当前需要修复的是拟合与验证流程，保持已确认的共同停止、目标和可行性定义。

下一步建议是一轮有上限的离线修复，具体协议见[待批准登记](../config/nav065_saved_refit_proposal_v2.json)：

1. 复用现有540条train轨迹，不再采新回合；固定六个actor与整套v2，仅更新双critic。
2. 保留原共同停止真值。以起点、沿途、预算边界三个回归项等权训练，边界只按train真值选取。拟采用学习率0.0001、每候选最多300次新增更新；这些是待验证的工程设置，不是论文规定的数值。
3. 先检查每候选全部90个train起点：零假可行、主预算18/18识别及原误差项必须通过；没有通过则停止，不查看新的开发预测、不发布包。
4. 六候选全部通过train检查后，固定权重，对原180条development轨迹统一复验一次。保持beta=0、每候选零假可行及主预算6/6等原标准。开发集已查看的事实保留，不把复验当独立最终测试。
5. 任一开发候选未过则保留本轮失败，不追加更新或调阈值。G4通过后才开始NAV-066独立预算选择。
