## 原理与统一接口

采用预算增广状态：`y`记录危险区域访问历史，`z`记录剩余预算；策略网络生成速度指令，两评价网络分别评价到达/安全及成本。RC-PPO的共同停止、两critic学习目标、三套估计器/联合GAE与最小化PPO需在实际训练链中一致，不能由普通奖励PPO或经验标签扫描替代。Go2观测、速度动作、PyTorch和J单位允许做工程适配。

| 接口 | 固定要求 |
| --- | --- |
| 导航输入 | 仿真真值状态、地图/目标、安全历史、预算、剩余时间及功率模型所需历史；新版字段在NAV-061/062冻结 |
| 策略输出 | 机身系 `[vx, vy, yaw_rate]`；动作映射、实际应用值和概率计算一致 |
| 控制时序 | 上层10 Hz、底层重新观测推理50 Hz、物理200 Hz；关节动作不能保持0.1秒代替底层反馈 |
| 内部步成本 | 冻结名义功率模型的0.1秒能量，完整方法以 `(1+α)c`扣预算 |
| 执行成本 | 200 Hz逐关节正机械功积分，单位J；与内部模型成本分别记录，不称电池电能 |
| 安全几何 | 完整姿态足迹和冻结δ；初始通道净宽7–8 m，并验证膨胀后通路及30秒可达性 |
| 物理事件 | 200 Hz子步更新碰撞/危险/到达与active掩码；不能仅凭上层两端或末态推断全程安全 |

当前预算裁剪、负预算终止、目标内安全符号、失败尾项及30秒终点bootstrap存在待修点；最终公式和真值表须先在NAV-061裁定，再由NAV-062/063实现与独立验收。该说明没有把拟修正设计写成已实现事实。

服务器任务固定 **tiger11（192.168.20.11）+tmux**，现场核验hostname、GPU、绝对解释器、资源与输出目录；不使用.10或自动转到.12。Windows文档维护与静态检查例外。

前置回修按计划 `upstream_correction_policy`执行：问题、原版本、修正、复验和下游影响追加到当前任务；保留旧工作记录、失败和产物，失效门禁重验后再推进。论文、冻结资源、旧校准和[RC-PPO](../../RC-PPO/README.md)/[HiRA](../../HiRA/README.md)保持只读。历史HiRA独立复核不默认阻塞v2，涉及共享代码时检查实际影响。
