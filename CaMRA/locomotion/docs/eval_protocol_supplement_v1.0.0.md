变体集合由 `program_variants()` 唯一定义，**按实际 4 个对角组合计数**：
`lateral` 2 个（`vy=±0.3`）、`turn_inplace` 2 个（`wz=±0.8`）、
`combined` 4 个 `(+,+,+)、(+,−,−)、(−,+,−)、(−,−,+)`。
父协议写 `sign_combinations: 4`，其含义就是这 4 个，**不是全部 8 种**，报告不得写成“覆盖全部 8 种”。

## 4. 判定规则

对每个 `(group, scenario, variant)`：

1. 该变体的 300 回合中，父协议该场景列出的每条指标都满足阈值（`perturbed` 组 `rmse_*` 按父协议放宽 20%，
   `failure_rate ≤ 0.10`），记为达标；
2. 指标有效回合数 < 90% 时，该指标判“证据不足”，该变体**不得**判达标，也不得改判“失败”——
   报告须单列“证据不足”，并阻止 `overall_pass`；
3. 缺任一变体（该变体回合数为 0 或未达配额）→ 该场景判**未覆盖**，等同不通过。

场景级：所有变体均达标 → 场景通过。
组级（沿用父协议）：`nominal` 全部场景通过；`perturbed` 通过率 ≥ 80%；
全局失败率 ≤ 0.05（nominal）/ ≤ 0.10（perturbed）。
以上全部成立且无“证据不足”项 → `overall_pass`。

报告必须同时给出：逐变体表（回合数、终止原因、各指标值与有效数、判定）与场景合并值（仅对照）。
