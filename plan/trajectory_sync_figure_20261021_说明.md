## 1. 要完成的图片

制作一张基于假设数据的案例图，帮助审阅论文的论证逻辑和绘图效果：左侧展示同一场景中两种方法的路线，右侧依次展示实际间隙、累计成本与预算、线速度跟踪误差。

| 面板 | 展示内容 | 需要读者理解的关系 |
| --- | --- | --- |
| 左侧轨迹 | 实体障碍、机器人尺度、起点与目标、名义与实际路线、关键事件 | 在哪里发生执行偏差，导航选择如何考虑空间余量 |
| 右上：实际间隙 | 两方法机身对实体障碍的最小间隙随时间变化，含接触边界 | 地图中的近障位置对应什么安全余量 |
| 右中：成本与预算 | 两方法实际累计成本、初始预算及必要的名义成本参照 | 名义估计与实际执行成本的差异，以及预算是否被突破 |
| 右下：跟踪误差 | 两方法实际速度与指令速度之差，单位 m/s | 共享低层接口仍存在执行误差，校准需要考虑这种失配 |

蓝色 `#0072B2` 固定表示 HD-MCRA，橙色 `#D55E00` 固定表示未校准 RC-PPO。实际路线用实线，名义参照用同色浅虚线；所有面板保持同一套编码。

图片服务于论文的核心工作：将 RC-PPO/MCRA 应用到真实四足机器人时，通过冻结低层速度接口、成本校准 α 和空间余量 δ，处理执行带来的失配。本样图用于解释这种机制，不能替代真实部署验证。

## 2. 数据如何构造

原始运动记录逐点编写，可以同时参考多个过去时刻、整个运动阶段和后续过程的连贯性。不能用一套通用曲线公式、批量随机噪声或少量关键帧插值，代替全部原始样本。

每个原始样本显式存入静态 CSV/JSON。起步、转弯、近障、修正和恢复应有连续的运动背景；波动应有大小、持续时间和相关性，避免机械重复或不合理跳变。构造依据按阶段和关键事件记录，异常点单独解释。

脚本负责读取固定数据、计算关联量、校验和绘图。实际速度与实际位姿选择一种作为权威原始记录，另一种通过明确的离散运动学换算；间隙、误差、累计成本和预算从同一份记录计算。绘图时不重新造数、加噪声或平滑原始运动。

任务 8、9 分别逐点编写 RC-PPO、HD-MCRA 对应的假设数据。“全程”是指数据覆盖从初始到终止的完整过程，不要求训练模型、运行策略代码或机器人仿真。后续运行的代码用于关联量计算、数据校验和绘图。

计算与绘图使用本机已有的 `py39` Conda 环境：`D:/codesoftware/Miniconda/envs/py39`。已核实 Python 3.9.21、NumPy 1.26.0、Pandas 2.2.3、SciPy 1.13.1、Matplotlib 3.9.4 和 Pillow 11.2.1；库导入、表格计算及内存 PNG/PDF 导出检查均通过，无需为核心计算和绘图安装新依赖。执行时将环境版本及复现命令归档；附加功能按实际需要检查。

## 3. 与论文及已有假定结果的关系

以 [CCDC 最新稿](C:/Users/smile/Desktop/paper/CCDC/latex/1020/main.tex) 为核对来源，执行时重新确认原文和口径。

| 已有内容 | 本图如何使用 |
| --- | --- |
| α = 0.18，δ = 0.12 m，校准分位数 0.90，均为假设值 | 沿用参数语义；不把 α 当成成本降低比例，不把 δ 当成实际最低间隙或误差硬上界 |
| 主表 HD-MCRA / RC-PPO：SR 73.3 / 70.7%，CR 15.0 / 15.7%，Cost 88.3 / 91.7，BVR 9.0 / 14.0%，MC 0.31 / 0.30 m，均为假设值 | 用于核对整体叙事；单次案例不必等于总体均值，也不能推导出这些统计结果 |
| 消融表与主表的占位结果不同 | 分别记录来源和口径，不混成同一批实验 |
| 跟踪 RMSE 0.19 → 0.08，假设值 | 原属关节空间与速度接口对照，不能套给本图两个共享低层接口的方法 |
| 高层间隔 0.2 s、最长 30 s、速度及角速度命令范围，均为假设配置 | 约束案例时间和运动尺度；实际运动与命令域分开检查 |
| 成本函数、机器人足迹、预算状态来源等尚有未核实项 | 明确制定仅用于本图的示例约定，记录为新增假设 |

两方法使用相同地图、起点、目标、机器人几何、低层接口和可比扰动，优先采用共同初始预算。先确定成本、预算和终止规则，再编写数据，不根据成图结果调整阈值制造优势。

允许本方法绕行、减速、出现局部较高成本，允许两条误差曲线接近或交叉。α 处理成本余量，δ 处理空间余量；它们并不直接消除跟踪误差。不同方法经过同一位置的时间可以不同，地图事件与各自曲线的时间必须对应。

## 7. 四个阶段如何审查与纠偏

| 审查节点 | 审查重点 | 通过后进入 |
| --- | --- | --- |
| REVIEW-001：方案确定后 | 前五项任务是否相互一致；场景是否合理；单位、坐标、足迹、成本、预算及终止定义是否明确；字段能否支持所需计算 | 计算实现与小段数据 |
| REVIEW-002：小段完成后 | 转弯滞后与恢复是否连贯；波动是否合理；计算是否正确；轨迹、间隙、误差、成本是否能相互解释 | 两组全程数据编写 |
| TASK-010：完整数据完成后 | 整段运动、比较条件和论文关联是否合理；是否刻意制造优势；前两次审查结论是否仍有效 | 正式绘制各面板 |
| TASK-014：完整图完成后 | 图片是否忠实呈现数据；事件和数值是否对应；论证是否清楚；视觉细节是否对齐参考 | 复现检查与交付 |

每次审查都读取实际文件和结果，不能仅依据任务已标记完成。问题记录在 `output/reviews/issues.json`，包括发现问题的节点、证据、来源任务、影响范围、根因、修正内容及版本、复查方法和结果。状态依次为 `open`、`corrected_pending_recheck`、`closed`；没有发现问题也要保留检查内容与证据。

发现问题后先定位来源，再修正，最后检查受影响的后续内容。例如，间隙曲线异常若来自机器人足迹定义，就回到场景约定修正，重新计算和检查相关数据，而不是直接调整曲线。涉及原始点的修正必须修改静态数据记录并保留版本。

如果问题使某个已完成任务的验收失效，就追加失效原因，将该任务及已完成的依赖后继设为待复验，清空当前验收结论，保留历史工作记录。按原依赖顺序重新验收；对实际未受影响的内容，只确认原证据仍有效，无需全部重做。回溯不增加反向依赖，避免形成循环。

四份阶段报告分别为 `01_design_review.md`、`02_pilot_review.md`、`03_full_data_review.md`、`04_figure_review.md`。所有影响当前阶段验收的问题闭合后，才进入下一阶段。常规审查与已授权范围内的修正由执行者完成，不增加逐阶段用户审批。
