## 1. 绘图目标与论文定位

本图解释论文的核心工程工作：把 RC-PPO/MCRA 接入四足机器人的执行闭环，通过同一冻结速度接口，测量执行带来的成本和轨迹偏差，再将偏差转化为学习与部署使用的校准裕量。

读者看完应能回答三个问题：高层指令怎样作用于机器人；执行成本偏高时怎样预留预算；实际轨迹偏离名义轨迹时怎样预留安全空间。低层强化学习和 RC-PPO 保留必要接口及算法位置，图面重点放在三项工程设计及其联系。

本图定位为方法与部署总览，拟作为 [当前架构图](C:/Users/smile/Desktop/paper/CCDC/images/1020/framework_overview_final.png) 的替代候选。已有“轨迹＋同步曲线”案例图继续保留：总览图讲设计与作用位置，案例图讲路线和相关指标之间的关系。本计划交付候选图、图注、替换片段和独立排版预览；正式论文接入由后续明确的编辑任务完成。

## 3. 方法流程与关键接线

离线流程依次为：冻结速度接口 → 获取名义／执行配对记录 → 计算成本超支与轨迹偏差 → 估计 α、δ → 在校正条件下进行高层学习 → 选择最小已测试可行初始预算 → 将策略和预算分别传入在线模块。

在线闭环为：观测与剩余预算 → 高层策略 → 速度指令 → 同一冻结跟踪器 → 机器人／环境 → 反馈与预算更新。实际累计成本单独记录，与内部校正计费区分。

| 对象 | 正确作用位置 | 审查重点 |
| --- | --- | --- |
| 冻结跟踪器 | 贯穿误差测量、校准、学习和部署的执行接口 | 冻结参数不代表零误差、确定性物理过程或已证明稳定性 |
| 配对记录 | 相同初态、地图、目标和高层命令序列 | 同一时刻配对；校准、预算选择和最终评价使用分开的记录集合 |
| α | c̃=(1+α)c，进而影响预算更新 | 不能直连速度命令，也不能标为节能比例 |
| δ | 额外膨胀危险区域 | 不是降低跟踪误差的控制增益，不能重复计算机器人足迹 |
| α、δ 的估计 | 高层学习之前的离线校准 | 单条示例不等于完整校准集；不画成在线自适应 |
| Phase I | 校正条件下的 actor／critic 学习 | 概括继承的 RC-PPO 组件，保持工程主线的视觉优先级 |
| Phase II | 学习后在候选预算上进行评估 | 表达最小已测试可行预算，避免连续全局最优含义 |

若图中出现增广状态 y，应保持安全历史的含义，不误作航向。成本计算依赖的状态来源、执行数据来源等尚未核实的细节，使用已确认的通用表述并列入未决项。

## 6. 怎样定期回顾并及时微调

每次审查按五步完成：

1. 对照本阶段验收条件与原始绘图目标，检查实际数据、文件和图像。
2. 定位到来源、语义、计算、渲染、标注或排版层，关联具体任务。
3. 在新工作区内修正并保存新版本，说明下游影响。
4. 重做受影响检查并重新看图，有证据后关闭问题。
5. 影响本阶段验收的问题全部解决后，才将 REVIEW 设为 true。

例如 C 的 δ 边界错误，应先检查基础障碍是否已含足迹，再修数据约定或计算。B 把校正计费误标为实际成本时，同时复查 D 的预算模块和图注。

若修正使上游已完成验收失效，追加说明，将该任务及受影响的已完成后续任务改回 false，清空当前验证结论，保留历史记录，再按依赖重验。即使审查未发现问题，也记录检查对象与结果。

### 9.3 下方模块分别做什么，怎么连接

| 模块或功能区 | 接收什么 | 负责什么 | 输出给谁 |
| --- | --- | --- | --- |
| 导航观测与剩余预算 | 机器人/环境状态、目标，以及成本计费更新 | 整理导航所需信息并维护预算 | 高层导航策略 |

| 冻结速度跟踪器 | 速度命令、本体感知 | 把速度要求转换为关节指令，整个校准和部署过程使用同一套固定参数 | 机器人 |

| 校正条件下的高层学习，离线 | 校正后的成本、危险区域及继承的 RC-PPO 学习框架 | 在已校正条件下学习策略，并完成候选初始预算选择 | 部署策略及初始预算 |

图中需要明确的连接包括：

1. 观测/剩余预算 → 高层策略 → 速度命令 → 冻结跟踪器 → 关节指令 → 机器人。
2. 机器人状态返回导航观测；本体感知返回跟踪器。两类反馈可以共享线段，但用途必须清楚。
3. 校正计费更新剩余预算；实际累计成本单独记录，二者不混称。
4. 配对记录 → 离线校准 → α/δ → 两类校正条件 → 高层学习 → 部署策略/初始预算。
5. α 也用于部署中的预算计费；δ 表示危险区域的额外空间裕量。

α/δ 在高层学习前确定。图中不能把它们画成在线变化的控制增益、直接修改速度的模块，或实时改变原始传感器读数的模块。

实线优先表示在线信号，虚线表示离线训练或固定参数关系，并配短图例。训练 actor/critic 若有展示，仅在离线学习模块中概括其角色；不添加没有论文依据的网络层、维度、教师学生结构，不将 critic 画作在线控制器。

### 9.6 场景叠轨迹要怎样保证正确

继续读取原 v2 的 hd_mcra 名义/执行配对，不能拿两种方法的执行路线冒充误差。名义路线来自理想命令积分，执行路线来自既有假设速度数据；叠入场景不会使它们变成真实仿真日志。

先在低分辨率小样中完成以下检查，再制作正式图：

1. 统一世界坐标、单位、相机和图像裁切参数；优先选择俯视或近俯视镜头。
2. 检查起终点、三个障碍中心及边界的投影锚点，源渲染图上的重投影误差目标不超过2 px。
3. 路线和安全边界使用同一投影，正确处理遮挡；局部放大使用同一几何数据，不独立移动点。
4. 配对偏差连接相同时刻的两个位置；不加噪声、不平滑、不拉伸坐标、不人为放大误差。

### 11.4 成本场景怎么表达多次执行与裕量

背景沿用MuJoCo/EGL中可追溯的Go2、地面、障碍物和导航目标。优先展示3条路线，只有清楚且确有说明需要时才增加，最多5条。路线细、半透明、使用同色系和R1–R5标识，不增加无关机器人姿态或复杂地形。

路线旁放紧凑的相对成本超支条，路线ID与条形ID一一对应；每个执行成本与自己的名义成本比较。条形共用零点和同一比率尺度，α使用相同尺度的裕量标记。共用命令与名义模型条件时可以只画一条浅虚线名义路线；不能把不同命令的执行都拿来和同一名义记录比较。

多条路线说明“同一任务存在不同执行表现”，成本条说明“对应额外开销与预留α”。路线长短、分散程度或障碍间距不能单独推出成本大小，也不能把α画成地面上的包络或米制安全边界；后者属于C的δ表达。

当前α=0.18是原稿假设配置，不是本次几条路线计算出的最大值或实测分位数。图中的少量样本不能证明覆盖率、预算违规改善或任意扰动下都够用；不为让图好看而强制所有条形都在α以内。
